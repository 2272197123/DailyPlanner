# PRD: 恰饭板块（替换记账）

## 背景

删除记账板块（Ledger），替换为「恰饭」板块：解决"今天吃什么"。参考卡片设计 `research/ref-tricky-robin.html/.css`（uiverse ElSombrero2/tricky-robin-67，翻面卡：正面图片、反面描述，MIT）。

## 需求

### 核心流程
1. 用户选择餐次（中餐/晚餐）并输入预算范围
2. 系统在预算范围内的菜品库中随机抽取，以**老虎机抽奖动画**呈现（菜品名称/图片快速滚动后减速定格）
3. 抽中后展示**翻面食物卡**：正面 = 食物图片（像素风缩略图）；背面 = 名称、描述、预算价格
4. 用户可「就吃这个」→ 自动在当日计划创建**钉时任务**（中餐默认 12:00-13:00，晚餐默认 18:00-19:00，创建前用户可改时间）；或「再抽一次」

### 菜品库
- 首版由 AI 起草 60-100 道（家常/川湘/粤式/日韩/面食/快餐等分类），字段：名称、描述、参考价（预算匹配依据）、餐次（中/晚/均可）、分类、图片文件名
- **用户在界面里可增删改菜品**（菜品管理 UI）
- 菜品数据存后端（新表 dishes，三套方言 schema + init_mysql.sql）

### 记账板块移除
- 移除前端 LedgerView 入口（路由/导航/侧栏）与 accounting 组件
- 后端记账接口可保留代码但从前端不可达（最小风险）；DB 表不动

### 食物图片
- 图片由用户用 kimiwork 生图（提示词见 `research/kimiwork-image-prompt.md`），生成后放入 `frontend/public/food/`
- 前端按菜品记录的 `image` 字段引用；**缺图时显示像素风占位图**（程序化生成或通用占位），不能用 emoji 代替菜品图
- 卡片正面图片区域在缺图时也需美观

## 约束

- 钉时任务创建必须遵守 orderCfg v2 钉时铁律（spec/backend/quality-guidelines.md）：走 schedule store 现有的 addBlock/updateBlock 链路，钉时块不可被流动操作推挤
- 老虎机动画只用 transform/opacity；reduced-motion 下简化为直接定格
- 移动端适配（≤768px）；chrome80 CSS 约束
- 抽取公平性：服务端或前端 crypto.getRandomValues 随机；同一餐次连续抽取不重复上一次结果（除非范围内只有 1 道菜）
- 预算过滤：菜品参考价 ≤ 用户预算上限（可选下限）

## 验收标准

1. 侧栏/路由中记账板块消失，「恰饭」板块出现
2. 输入预算 + 选餐次 → 老虎机动画 → 抽中菜品翻面卡（正面图/背面名称+描述+预算）
3. 「就吃这个」→ 当日计划出现钉时任务（默认时间正确，可改）；任务卡显示菜品名
4. 菜品管理界面可增删改，改动持久化（刷新/换设备保留）
5. 预算过滤正确（抽中的菜不超预算）；缺图菜品显示占位图
6. 移动端正常；reduced-motion 降级；`npm run build` 通过；e2e 不回归
