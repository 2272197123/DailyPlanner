# 存档系统重写 — 历史锁定+快照独立存储+自评导出+AI评价

## Goal

将每日数据从"共享模板渲染"改为"每日独立副本 + 存档锁定"架构。每天的数据副本在首次访问时从模板 Copy，之后独立修改；存档后进入只读状态，支持自评、AI分析评价、导出。

## 架构决策

**存储模型**：模板-副本分离（Copy-on-Write + 仅向前传播）

- 全局日课模板（`store.routines`）：仅作为"出厂配置"，不直接用于渲染
- 每日独立副本（`dp_day_data_{date}`）：每个日期的 blocks + routines + 目标快照
- 模板修改仅影响尚未初始化的未来日期，已存档/已初始化的日期完全隔离
- "推送到模板"操作：将当天改动同步到全局模板 → 仅影响未来新日期

## Requirements

### R1：每日独立数据副本
- R1.1：日期首次访问时，从日课模板和目标状态 Copy 生成当日副本
- R1.2：当天所有编辑（任务增删改、日课调整、完成勾选）仅写入当日副本
- R1.3：已初始化日期的副本不再受全局模板修改的影响
- R1.4："推送到模板"仅更新全局预设，不回溯更新任何已初始化的日期

### R2：存档与锁定
- R2.1：存档时间由用户自定义（默认 23:30），可提前或延后
- R2.2：到达存档时间后，系统提醒用户进行自评
- R2.3：自评内容：用户对当日打分（1-5 星）+ 文字总结
- R2.4：存档后该日期数据进入只读状态，禁止任何修改
- R2.5：存档快照独立存储（localStorage + 服务器双写），与活跃数据解耦

### R3：AI 评价生成
- R3.1：存档时自动调用 AI API 分析当日完成情况
- R3.2：AI 评价内容包括：完成情况总结、任务完成率、心态评估、鼓励话语
- R3.3：AI 人设通过预设 prompt 定义，支持用户自行修改（默认：循循善诱的老师）
- R3.4：AI 评价文字随存档永久保存，历史日期查看时展示

### R4：导出
- R4.1：支持导出为 Markdown 格式（自评 + AI评价 + 任务明细 + 统计）
- R4.2：支持导出为 PDF 格式
- R4.3：导出时自动附带该日的完成统计数据

### R5：历史日期查看
- R5.1：导航到历史日期（含存档日期）时，读取存档快照渲染（只读）
- R5.2：显示当日完成统计 + AI 评价 + 任务明细
- R5.3：不可编辑、不可勾选、不可拖拽
- R5.4：如果某历史日期未存档（已初始化但未锁），显示警告并允许手动存档

## Acceptance Criteria

- [ ] AC1：修改今天的日课副本 → 检查昨天和明天的日课数据 → 确认不受影响
- [ ] AC2：存档今天 → 导航回今天 → 确认所有编辑操作被拦截
- [ ] AC3：修改全局日课模板 → 导航到明天（未初始化） → 确认使用新模板
- [ ] AC4：导航到上周已存档日期 → 确认只读且有 AI 评价展示
- [ ] AC5：导出自评 + AI评价为 md 文件 → 确认内容完整
- [ ] AC6：修改 AI 人设 prompt → 下次存档时 AI 评价风格变化

## Out of Scope

- 跨设备同步（依赖服务器端的后续改造）
- 纯离线模式下的 AI 评价（需要 API Key）
