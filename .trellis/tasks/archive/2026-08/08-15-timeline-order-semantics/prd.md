# PRD: 时间轴排序语义修正——钉时块起止永不被流动块影响

## 用户反馈（原话）

「流动任务挪到固定任务之前会影响固定任务的起止时间。流动任务的时间应该整体安排在钉时任务之前或之后且不影响钉时任务的起点与终点。事实上在排序上他们完全等价，只是固定任务的开始时间是确定好不能变的，流动任务的开始时间可以计算改变。」

## 现状与疑似病因

- `getComputedTimeline`：钉时块按 `block.time` 固定；流动块从 timelineStart 顺排、遇钉时跳过。这部分语义本就「钉时不变」。
- 但拖拽落点（`resolveDrop`）存在已知缺陷：流动块落到钉时块之前的间隙时，`beforeId` 是钉时 id，`flowIds.indexOf` 得 -1 → 被追加到流动序**末尾**（视觉落点与结果不一致）；「落到钉时块上=钉住」的冲突顺延（settle）逻辑也有误改既有钉时块时间的嫌疑。**实施第一步必须用 CDP 复现用户描述的现象，定位到底是哪条路径改了钉时块的起止，再修。**

## 需求

### R1 钉时块不可变（铁律）

任何针对**流动块**的操作（拖拽重排、落间隙、落到钉时块上、新建、导入、删除其他块）都不得改变任何既有钉时块的 `time`/`duration`。钉时块时间只能由「显式编辑时间（轮盘/拖杆）」或「拖动该钉时块本身」改变。

### R2 全局顺序等价

- `orderCfg.order` 升级为**全局顺序**（钉时 + 流动 id 都在其中，即用户的排列意图）；兼容旧数据（旧 order 只含流动 id 或混合——排序时未知 id 按既有规则兜底）。
- 时间推算：钉时块按 time 固定排序；流动块按全局顺序依次放入钉时块之间的空档（gap），从 timelineStart 起：
  - 排在钉时块 P 之前的流动块必须整体放入 P 开始之前的空档（`[cursor, P.start)`），不得与 P 重叠；
  - 空档放不下的流动块，顺延到 P 结束之后的空档继续按顺序放（保持流动块间相对顺序，钉时不动）；
  - 显示按计算时间排序（并列按全局顺序索引），在物理可行时与用户排列一致。
- 拖拽落点修正：流动块落到钉时块**之前的间隙** = 插入到全局顺序中该位置（不再追加到末尾）；落到钉时块**身上** = 钉住（时间=目标开始，冲突只顺延被拖块自身）；拖钉时块 = 改被拖块时间（现状保留）。

### R3 不回归

- 完成切换、庆祝动画、导入、周期规则物化、星轨轮盘/星图拖杆/星历横条、触屏长按拖拽均不回归。

## 验收

- A1（复现）：先复现原 bug 并记录病因；修复后同一路径下钉时块起止不变。
- A2：流动块拖到钉时块前间隙 → 出现在该位置且时间整体在钉时块之前；空档不足时顺延到其后，钉时块起止不变。
- A3：刷新/重新进入后顺序与时间都保持（orderCfg 持久化）。
- A4：CDP 桌面 + 移动触摸各跑一遍拖拽回归；`npm run build` 通过。
- A5：部署生产。
